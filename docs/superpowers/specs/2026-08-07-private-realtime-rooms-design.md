# gyeot 비공개 실시간 작업실 MVP 설계

날짜: 2026-08-07

## 목표

가입 절차나 개인정보 수집 없이, 두 명 이상이 초대 링크 또는 초대 코드로 같은
비공개 작업실에 입장한다. 각 앱은 자기 컴퓨터에서 AI 세션을 감지하고, 방에는
작업 상태, 동물, 소개글, 일시적인 이모티콘만 실시간으로 공유한다.

## 범위

### 포함

- 이메일·비밀번호·OAuth·공개 프로필이 없는 익명 입장
- 방 만들기, 초대 링크 복사, 초대 코드 붙여넣기 입장
- 최대 10명의 비공개 방
- 자동 생성 별명과 동물의 종 일치 기본값
- 동물, 한 줄 소개, 작업 중/자리 비움, 세션 시작 시각의 실시간 동기화
- 이모티콘의 실시간 전파와 4초 표시
- 연결 끊김, 재연결, 만료·잘못된 초대, 방 정원 초과 처리
- Supabase RLS 및 비공개 Realtime 채널을 사용한 방 단위 권한 분리

### 제외

- 이메일·비밀번호·소셜 로그인과 계정 복구
- 친구 목록, 검색 가능한 공개 프로필, 공개 작업실
- 영구 채팅과 이모티콘 이력
- 프롬프트, 파일 경로, 코드, 프로세스 목록, 실제 컴퓨터 식별 정보의 수집
- 독립적인 웹 초대 랜딩 페이지와 앱 미설치 사용자의 설치 유도

## 사용자 경험

### 첫 실행

1. 앱은 Supabase 익명 인증으로 내부 식별자를 한 번 만든다.
2. 앱은 `느긋한 여우`, `다정한 곰`처럼 형용사와 종을 조합한 별명을 고른다.
3. 이때 종은 별명 속 동물과 동일하게 설정한다. 별명과 종은 이후 각각 수정할 수
   있으며, 한쪽을 바꿔도 다른 쪽을 강제로 변경하지 않는다.
4. 사용자는 `방 만들기` 또는 초대 링크/코드로 `방 참여` 중 하나를 선택한다.

### 방 만들기와 참여

- 방 생성자는 새 비공개 방을 만들고, 7일 동안 재사용 가능한 단일 초대 토큰을
  받는다. MVP에서는 초대 토큰을 일찍 무효화하는 UI를 제공하지 않는다.
- 앱은 `gyeot://join/<token>` 형식의 초대 링크와 사람이 붙여넣을 수 있는 초대
  코드를 함께 제공한다. 링크는 앱이 설치된 환경에서 방 참여 화면을 연다.
- 초대 토큰을 받은 사용자는 해당 방에 최대 10명까지 입장한다. 이미 방 구성원인
  사용자가 재입장하면 정원을 다시 차지하지 않는다.
- 초대 토큰 원문은 데이터베이스에 저장하지 않고 해시만 저장한다.

### 동기화

- 기존 Rust 로컬 감지는 계속 각 기기에서 4초 간격으로 동작한다.
- React의 방 클라이언트는 자기 상태(`active`, `started_at`, `last_seen_at`)와
  프로필(`display_name`, `species`, `intro`)을 서버로 보낸다.
- 활동 상태는 로컬 감지의 결과만 보낸다. 도구 이름, 프로세스 이름, 프롬프트,
  파일 경로는 전송하지 않는다.
- 연결된 클라이언트는 같은 방 구성원 행의 변경을 구독하여 좌석, 소개글, 동물,
  작업 상태를 즉시 갱신한다.
- 15초 넘게 갱신되지 않은 참여자는 오프라인으로 표시한다. 성공적으로
  재연결되면 같은 익명 ID와 프로필로 자동 복귀한다.
- 이모티콘은 방의 비공개 Realtime Broadcast로 보낸다. 수신자는 4초간 표시하고
  저장하거나 재연결 후 재생하지 않는다.

## 데이터 및 권한

### 내부 신원

Supabase 익명 인증은 이메일이나 기타 PII 없이 UUID 기반 사용자를 만든다. 이
UUID는 방 권한과 자기 참여 행 판별에만 쓴다. 앱 저장소를 지우면 사용자는 새
익명 ID가 되고 이전 방 권한은 사라진다.

익명 사용자 레코드는 자동 삭제되지 않으므로, 30일 이상 지난 익명 인증 사용자와
오래된 비활성 방·참여 행을 정리하는 서버 측 정리 작업을 둔다.

### 테이블

- `rooms`: 방 ID, 생성 시각, 최대 인원(항상 10), 마지막 활동 시각
- `room_invites`: 방 ID, 초대 토큰 해시, 생성 시각, 만료 시각
- `room_members`: 방 ID, 익명 사용자 ID, 표시 이름, 종, 소개글, 활동 여부,
  세션 시작 시각, 마지막 heartbeat 시각, 입장 시각

`room_members`는 `(room_id, user_id)`가 유일하다. `create_room` 보안 정의 RPC는
방·초대 토큰 해시·생성자 참여 행을 하나의 트랜잭션으로 만들고, `join_room` 보안
정의 RPC는 토큰 해시와 만료 시각 검증·기존 참여 확인·10명 정원 확인·구성원
생성(또는 갱신)을 하나의 트랜잭션에서 수행한다.

모든 공개 스키마 테이블은 RLS를 켠다. 사용자는 자신이 구성원인 방의
`room_members`만 읽을 수 있고, 자신의 행만 갱신할 수 있다. 초대 토큰 검증과
구성원 추가는 `create_room` 또는 `join_room` RPC만 수행한다. Realtime Broadcast는
방 ID별 비공개 채널을 사용하고 같은 구성원 정책으로 구독을 제한한다.

## 클라이언트 구조

- `room-client`: 익명 로그인, 방 생성/참여, 프로필·heartbeat 쓰기, 변경 구독,
  broadcast, 재연결을 감싼다.
- `room-state`: 서버 구성원과 최근 이모티콘을 UI가 쓰기 쉬운 상태로 정규화한다.
- 기존 `App.tsx`: 로컬 감지 결과를 `room-client`에 전달하고, 하드코딩
  `previewRoomMates` 대신 `room-state`를 렌더링한다.
- `ForestCharacter`: 현재 종 API를 그대로 사용한다.

클라이언트는 한 번에 하나의 활성 방만 렌더링하고, 마지막으로 입장한 방 ID를
로컬에 보관한다. 다른 방에 다시 입장하면 그 방을 활성 방으로 바꾸되 기존 방의
서버 참여 행은 유지한다.

환경 변수에는 공개 가능한 Supabase 프로젝트 URL과 publishable key만 넣는다.
secret/service 키는 클라이언트나 Tauri 번들에 넣지 않는다.

## 오류 처리

- 만료·위조·알 수 없는 초대 토큰: 참여하지 않고 이해 가능한 오류를 표시한다.
- 10명 정원 초과: 기존 방 데이터는 보지 못하고 정원 초과를 표시한다.
- 네트워크 오류: 현재 로컬 UI는 유지하고 연결 상태를 표시한다. 2초, 5초, 10초,
  이후 30초 간격으로 재연결을 시도한다.
- 구독이 끊김: 재연결 뒤 현재 구성원 목록을 다시 읽어 누락된 변경을 보정한다.
- 앱 종료: 명시적 퇴장은 최적화일 뿐이며, heartbeat 만료가 최종 오프라인 판단이다.

## 검증

- 단위 테스트: 자동 별명·종 매칭, 참여자 정규화, 15초 오프라인 판정, 이모티콘
  4초 만료, 정원 표시.
- Supabase 로컬 통합 테스트: 초대 토큰 검증, 중복 입장, 10명 동시 입장 경합,
  RLS의 방 간 차단, 자기 행만 수정 가능함을 확인한다.
- 수동 E2E: 서로 다른 익명 ID의 앱 두 인스턴스에서 링크/코드 참여, 세션
  감지·소개글·동물·이모티콘 동기화, 오프라인·재연결을 확인한다.

## 성공 기준

- 새 사용자는 회원가입 없이 초대 링크 또는 코드로 같은 비공개 방에 들어간다.
- 두 사용자의 동물, 소개글, 작업 상태, 이모티콘이 각 상대 화면에 반영된다.
- 다른 방 참여자와 비구성원은 방 상태나 Realtime 채널에 접근할 수 없다.
- 어떤 경로에서도 AI 프롬프트·파일 경로·프로세스 정보·이메일을 전송하지 않는다.
